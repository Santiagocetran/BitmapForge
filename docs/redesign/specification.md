# The Bitmap Workbench — design specification

Version 1.1 · Mandatory audit revisions submitted for independent reapproval · source baseline `8c6613279ed856e4933608e7e6c04e91dca2b331`

Normative words **must** and **retain** are acceptance requirements, not claims of implementation. [Research](research.md) records evidence/alternatives. [State contracts](state-contracts.md) govern all cancellation, mounting, focus and cross-owner interfaces. [Implementation plan](implementation-plan.md) assigns exclusive files and verification.

## 1. Product structure

The primary result is a live specimen, not a welcome dashboard. Replace the all-open component stack with **Source / Look / Motion / Export** native task buttons. Exactly one is pressed; this is a named `role="group" aria-label="Editor tasks"`, not a partial tablist. Each is a native button with `aria-pressed` and `aria-controls` to its stable section ID. Enter/Space selects; ordinary Tab visits each; no arrow-key-tab emulation. Active panel is a named section with a visible 16px heading; inactive panels use `hidden`, with mounted children inside the current responsive inspector. Task changes are UI-only and do not mutate history or source settings.

Default task Source. Last active task remembered for this Layout lifetime, not serialized or persisted across browser sessions. No numbered steps, locked tasks, validation gate, automatic “next,” or implied completed state.

### Header and stage

Desktop header: static pixel-derived mark + BitmapForge; Undo/Redo; **Save .bitmapforge**, **Load .bitmapforge**, visible **Help**, **Export** primary. Show meaningful disabled Undo/Redo and accessible names. Do not display “Saved,” “Synced,” account/avatar, editable project title or invented filename. Save/Load are local files, distinct from generated assets. Preserve Ctrl/Cmd+S, undo/redo, R and `?` semantics, including typing exclusions.

Use a 56px desktop header, 8–16px outer spacing, 340px inspector with 16px inner padding, 12px stage gap. Preserve breakpoint 1024px. Desktop collapse contracts remain: a 44px-wide compact rail with accessible Expand settings, task shortcuts if they fit, and persistent global Export. Expand restores active task. Export expands/selects its own task and focuses its heading, never starts a job. Header is outside inspector scrolling.

At narrow widths, compact header may wrap to two intrinsic rows (brand/history then project/help); do not squeeze controls below target size or hide project controls solely behind hover. A pinned bottom **Open settings / Export** toolbar remains when modal closed. Toolbar height is content plus safe-area inset, not an overlay covering the canvas. Header/body/toolbar form the `100dvh` shell; body has `min-height:0; min-width:0`. Stage occupies remaining space. At 320px the controls reflow without document horizontal scrolling.

Main PreviewCanvas stays outside every task/disclosure/dialog branch and never changes key. Display-only changes: chrome, empty invitation, spinner treatment and optional textual current-source/renderer summary. No camera/zoom/fit/ruler, composition reset, scale change, engine hooks/lifecycle changes or new playback control. Existing background setting remains output content; editor theme never writes it.

### Source-aware empty invitation

Only display empty bridge for active model with no model, or active image with no image, when not loading and without status error. Heading 24–28px “Start with a source”; body “Choose a source, tune its look, then export.” Show four clearly named actions **3D model / Shapes / Text / Image**, plus existing **Try demo model** secondary and a route to project Load in header. For empty image, lead with “Choose an image” while retaining alternative routes. Do not cover actual loaded output or declare blank text an error.

Model/image stage actions navigate to Source, select requested input type through the existing setter and focus the corresponding native inspector Choose button; they do **not** synthesize a file chooser after an asynchronous modal transition. The subsequent native button activation opens the real picker. Shapes/Text select the existing source through the setter without overriding remembered shape/text configuration; no default change just for screenshots. Existing demo fetch stays unchanged. This is a display/navigation bridge, not an engine/source-loading rewrite.

Loaded source metadata is nondestructive and compact: source kind plus actual filename/size where present. No fake path, mesh count, render resolution or zoom readout. Long names truncate visually but retain full title/text accessibility. Replace is secondary; Remove is a quiet destructive text/border action, not the strongest color slab.

### Audit revision contracts R1–R3

Short empty stages keep the heading, guidance, four source routes and demo in a contained stage-only vertical scroller with ≥44px actions; no copy-driven canvas resizing/remount or document overflow. Help styling is mandatory A work: visible-viewport-bounded sibling content with pinned title/Close and a scrollable shortcut body, whole-interior scrolling only below 240px. Use the exact H/offsetTop rectangle, safe-area, explicit top/height/bottom:auto and shell formulas in [state contracts §3](state-contracts.md); `100dvh` alone is not the keyboard contract. Required captures include short empty and Help at 667×320, 320×568 and emulated reduced/nonzero-offset rectangles. Emulation is not real mobile-keyboard certification.

Task-body scrolling resets to start on explicit task activation, mobile reopen, desktop expand and either breakpoint crossing, while keeping active task/durable UI state. Ordinary task selection retains native-button focus; Tab visits remaining task buttons before panel fields. Same-breakpoint resize and Help do not reset the inspector. After commit, explicit source/Export focus/reveal overrides the reset and cannot be undone by stale jobs. Exact ordering and acceptance cases are in state contracts R2.

All nine selected-format actions must produce real artifacts on the final built UI. [Implementation plan §6.1](implementation-plan.md) is the finite per-ID ledger: retain original quality/runtime gates, add bounded GIF download-animation and Embed supported-source runtime/image-disabled cases, and prove React/Web Component UI dispatch separately from their existing builder-driven ASCII comparisons. No new format/builder/engine scope and no nine duplicated heavy quality suites.

## 3. Tokens and shared style contract (owner A)

Use existing system font stack; no remote font. Define CSS variables under `:root`, scoped class rules under `.bf-workbench` except portals, which receive their own `.bf-overlay` scope and inherited/global `--bf-*` tokens. Do not use broad `section`, `button` or wildcard descendants that override widget utility rules. Remove conflicting widget color utilities in owned JSX when adopting shared classes. Class contract is frozen before parallel work; A alone edits definitions.

Python WCAG sRGB luminance calculation executed during plan authoring: text/panel **14.66:1**; muted/field **7.78:1**; muted/hover **6.37:1**; accent-ink/accent **9.15:1**; accent/field **8.30:1**; boundary/panel **4.41:1**, boundary/field **3.79:1**, boundary/hover **3.11:1**; error/panel **9.75:1**; success/panel **10.68:1**. Fine-pointer controls may be 36px where specified; **palette edit/drag/move/delete targets remain ≥44×44 always**. Touch-facing navigation, Close and header commands are ≥44px. Four-pixel spacing rhythm: 4/8/12/16/24; 16px inspector heading; 13–14px principal labels; ≥12px essential metadata. Controls radius6, overlays10; stage quiet, not a card inside another card. Focus: 2px accent outline +2px offset against panel/workspace; selected and focus indicators coexist. Required edge always uses boundary, not separator.

Disabled uses native disabled, readable muted label plus obvious unavailable state; no opacity that destroys required adjacent text. Invalid adds error text/icon and `aria-invalid`/describedby, not red-only outline. Hover/focus never scales or shifts layout. No decorative motion; optional color transition ≤120ms, none under reduced motion. Spinner may be static progress indicator under reduce; actual artwork playback policy remains unchanged and must not be misrepresented as reduced-motion support.
