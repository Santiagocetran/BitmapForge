### Deliberate mounting choice: no new generic portal framework

Within each mounted responsive inspector, render four stable keyed sections and use `hidden` for inactive tasks. Do not conditionally return only the active widget; this preserves native disclosure state and gizmo/widget locals across task switches. Main preview remains outside. Existing desktop/mobile handoff **may remount the inspector widget subtree** (one rendered tree at a time), as baseline does. All durable UI state listed above is controlled in Layout, so remount does not lose it. Picker/drag transactions deliberately do not survive owner hiding; cancellation is required, not a lost-draft regression. No new stable inspector-host relocation/registry is introduced. No promise is made of gizmo-canvas identity across breakpoints; main-preview identity is mandatory.

Mobile close unmounts Radix Content and its widgets. Desktop collapse uses hidden without unmount. Task panels must not mount duplicate widgets in hidden desktop plus modal trees. Post-effects/native details must be controlled so close/resize does not discard expansion. Source configs already live in store. Do not add local-only Text advanced disclosure or palette browse state that disappears on responsive remount.

## 2. Frozen cross-owner APIs

These are the only new cross-widget interfaces. Reuse existing `uiPropValidators.js` validators where possible; A owns any shared validator addition required by audited lint. Workers must not edit that shared file concurrently.

### Layout → source and empty bridge

`InputSource({ navigationRef })`, optional object ref, publishes a minimal `{ focusSource(kind) }` handle in a layout effect, guarded cleanup so an old unmount cannot clear a newer handle. It **only** focuses already mounted visible controls: model Choose File, image Choose Image, current selected shape button, Text textarea. It never reads/writes engine/controller state, opens a native chooser or selects a source. Owner B keeps refs within InputSource and passes optional button/textarea refs to its children. Native Choose/Replace retains react-dropzone's real `open` on direct click/Enter/Space. Test ref cleanup and disabled/disconnected fallback; if no target, return false and A focuses Source heading. No global querySelector/name-dependent registration bus.

`PreviewCanvas({ onChooseSource })` optional callback, A-owned display-only prop. A's handler cancels palette first, chooses existing `setInputType(kind)`, selects Source, expands/opens inspector and records a pending source-focus request. After the newly committed Source is visible, A invokes `navigationRef.current.focusSource(kind)` once; otherwise Source heading fallback. Model/image stage action is navigation, not an immediate file picker. Native chooser remains a second explicit user activation; no asynchronously replayed hidden-input click. App/engine source effects unchanged.

### Layout → palette

Retain exact existing `portalContainer`, `interactionRef`, `presetDraft`, `onPresetDraftChange`, `presetSaveOpen`, `onPresetSaveOpenChange`. Add controlled `palettesOpen`, `onPalettesOpenChange` with standalone local fallback, default false. Controlled state lives only in A's Layout; C implements props and fallback/tests. No shared hook.

`interactionRef.current.cancel({ restoreFocus:false })` and synchronous `isKeyboardDragging()` remain exact shell contract. `cancel` must synchronously retire transaction/ref/focus generation **before** any queued blur can commit; React rendering of the closed picker may follow. No DOM event propagation broadening. Portal container remains inside active mobile Dialog.Content; desktop retains existing default portal. Popup collision/available-height limits remain valid in bottom sheet and short fallback.

### Layout → Look/motion

QualitySettings keeps optional `advancedOpen/onAdvancedOpenChange` and adds optional `postEffectsOpen/onPostEffectsOpenChange`; default false local fallback for standalone use. `part` is the finite enum `all` (default), `renderer`, `refinements`. Renderer part contains mode/relevant controls/dither; refinements contains Tone & background and Texture effects. Only one copy of each control is rendered in the integrated Look panel. A passes the same controlled disclosure state; D supplies component prop contracts and dedicated tests. Do not introduce arbitrary slots/config-driven forms.

Layout owns Composition's existing-style Rotation Offset/Light Direction wrappers and their open state. D owns widget contents, not shell disclosure callbacks. Keep both widgets mounted under hidden wrappers within the current inspector; no engine/GizmoCanvas edit.

### Project commands and Help

ExportPanel becomes output-only: selectedFormat/onSelectFormat/exportSelected/cancelExport/exporting/disabledReason, retaining output behavior. A owns the single header project input and direct props `{saveProject, loadProject}` from **the same** Layout controller; D removes only project presentation/unused props from ExportPanel. A updates integration callers/tests; D updates dedicated ExportPanel tests. No `useExportController`, `useExport`, manager/provider or save-hook invocation in Header/ExportPanel.

App supplies optional `onShowHelp` to Layout. That callback must run the same shared App help action used by `?`: committed bridge `beforeHelp()` then open sibling shortcuts dialog. Keep existing save/beforeHelp/restoreHelpFocus bridge layout-effect publication, identity-guarded cleanup and StrictMode behavior. No passive-effect replacement. Header Help and modal-local Help use same callback; modal-local Help is needed because header is inert behind inspector. Help remains sibling, not dialog content child.

## 3. Narrow-height geometry and accessibility

Desktop media query remains `(min-width:1024px)`. Below it, use existing Radix modal Dialog with Settings accessible title, bounded **bottom** content, overlay, background inert and focus containment. Keep accessible opener names **Open settings** and **Export**; Close visible text may say **Preview** with `aria-label="Close settings"` to make return-to-artwork explicit. This is not draggable, resizable, snap-point or nonmodal sheet scope.

Use the finite Layout-owned visible-rectangle adapter below. Default when effective height H ≥600px **and** portrait (window.innerWidth < H): sheet height S = min(0.6 × H, 560px), full viewport width, top T + H − S, explicit height S, bottom:auto, safe-area bottom padding inside border-box height. Content has pinned title/Close/Help row, pinned four task buttons, one stable notice slot, and one `min-height:0; flex:1; overflow-y:auto` task-body scroll. No sticky export action may cover fields; Export action/cancel are in its panel with bottom padding. At 390×844 the nominal sheet is 506.4px; the artwork portion above remains visible, dimmed/inert. This is a reference view, not live pointer manipulation.

Fallback when H <600px **or** landscape/square: S = H, top T, explicit height H, bottom:auto, own scrolling. At 320×568 and 667×320 this intentionally gives up the preview sliver. At 1023×768 landscape it is full height. No custom drag handle implying unsupported swipe interaction. Virtual-keyboard shrink changes size mode without closing, replacing controller or moving focus from the active input.

Title/nav rows must not shrink; notice may wrap and occupies intrinsic height. Extremely tall error text may scroll within notice region up to 25% available height, with accessible dismiss; body remains reachable. At pathological <240px available height, permit the whole dialog interior to scroll (title/nav included) rather than negative content height; Close remains first in DOM and reachable by Shift+Tab/Home scrolling. Test short fallback, long error, active input and last export control. Body scroll styles restore exactly on close.

### R1 — One visible-rectangle convention, empty stage and Help

The adapter is a small shell measurement, not a new controller/framework. Read `{ H: visualViewport.height, T: visualViewport.offsetTop }` when finite with H > 0; otherwise `{ H: window.innerHeight, T: 0 }`. T is the nonnegative layout-viewport Y coordinate of the visible top. Publish `--bf-visible-height` and `--bf-visible-top` on the document root so sibling Help portals receive the same rectangle. Initialize synchronously at mount; subscribe to window resize and visualViewport resize **and scroll** (offset can change without height), update only changed measurements, remove all listeners on cleanup. No polling, animation loop or focus work in this adapter. Without JS measurements the CSS fallback is H=`100dvh`, T=`0px`; measured pixel values replace, not add to, that fallback. Pinch-zoom is not a new application zoom feature.

Fixed shell/portal boxes are positioned in layout-viewport coordinates: visible interval `[T,T+H]`. The narrow shell uses `position:fixed; top:T; height:H; bottom:auto`, width:100%, border-box; remove conflicting old bottom/inset/translateY/centering constraints. Its header, minmax(0,1fr) body and intrinsic bottom toolbar are grid rows. Toolbar/safe padding consume space, not overlay it. Do not independently stack a `100dvh` child inside a measured-height shell. Inspector uses the S/top formulas above and bottom:auto, no vertical transform. Use the same convention for Help; no simultaneous top+bottom+height constraint. At ordinary desktop sizes retain existing layout. Adapter updates never remount the preview/controller or cancel an input transaction merely for height/offset changes.

**Empty invitation:** keep the observed canvas container’s sizing/ResizeObserver/lifetime intact. Inside the existing stage surface add a separate absolutely inset:0, min-width:0, min-height:0, overflow-y:auto, overflow-x:hidden invitation layer; use 12px internal padding and scroll-padding-block:12px. A max-width:480px inner block has margin-inline:auto and natural height; center vertically only when it fits (safe alignment, no negative translation). Four routes use a wrapping two-column grid, minmax(0,1fr), gap:8px; route/demo targets are at least 44px high, wrapping labels, demo follows routes. Retain heading, guidance and all five actions at short height; scroll the invitation, not the document or canvas, to reveal first/last action. Native focus plus instant nearest reveal must put the full focused target inside the invitation client rectangle intersected with `[T,T+H]`. Do not shrink targets or canvas backing size to fit copy. Loading/error conditions remain unchanged.

**Help, mandatory A responsibility:** sibling Radix dialog semantics/shortcuts/status freeze stay unchanged. Overlay covers `[T,T+H]`. Content width:min(480px,calc(100% - 16px)), centered horizontally, top:T+8px, max-height:calc(H - 16px), bottom:auto, transform only on X, border-box with safe-area padding inside. Use a nonshrinking title/Close row (Close at least 44×44) and min-height:0, overflow-y:auto shortcut body, 12px scroll padding; title/Close pinned outside the body. On H <240px use one whole-content vertical scroller, title/Close first, rather than a negative body; Close and last shortcut remain scroll reachable. Do not introduce a second Close or alter initial/restored focus. No footer covers shortcut rows. Root tokens apply outside workbench scope.

A-owned R1 cases in `ui-foundations.spec.js`: at 667×320 and 320×568, empty model **and** image, keyboard-reach all four routes/demo (fresh state for routes that remove invitation), Help button and `?`, Close and last shortcut; assert full target bounds inside visible intersection after scrolling, ≥44px targets, document scrollWidth ≤ clientWidth, same preview DOM node/manager before/after. Capture short empty and short Help. Emulate H=320,T=0 and H=280,T=40 on a 390×844 layout viewport by substituting only measurement getters/events before mount; assert shell, sheet and Help tops/bottoms against `[T,T+H]`, focus/last field visible, then same-breakpoint resize/scroll updates and cleanup. Include H=220,T=40 whole-interior fallback. These are adapter tests, not evidence of a physical mobile keyboard. Report real keyboard testing unavailable unless performed.

### R2 — Deliberately reset task scroll; reveal wins

The one task-body scroller is Layout-owned UI only. No per-task offsets, persistence or generalized scroll framework. Every explicit native task activation (including selecting the current task) resets `scrollTop=0` after the visible panel commits; keep focus on its task button, without autofocus. This exposes the active heading/first controls. Ordinary Tab traverses remaining task buttons in DOM order before panel controls; Shift+Tab works normally.

Mobile close resets the discarded body; reopen starts at 0 with Close focus. Desktop collapse resets before hide; expand starts at 0 and retains the documented focus policy. Both breakpoint directions reset the newly visible inspector body to 0; desktop→narrow leaves it closed, later open starts at 0; narrow→desktop may then reveal/focus the owner heading as required by the transition matrix. Active task and durable disclosures/drafts are still retained. Same-breakpoint height/offset changes do **not** reset scroll: preserve the active input and reveal it only if clipping would otherwise occur. Help open/close does not reset the inactive inspector.

Order within the existing transition generation: cancel/invalidate first, commit visibility, set task-body scrollTop=0 for reset transitions, then perform that generation’s explicit Export/source/resize-owner focus and instant nearest reveal. Explicit source/Export reveal wins, even when its target is far below the heading. Use the existing one-shot postcommit request, clear it upon consumption; no setTimeout, smooth scroll, retrying frame loop, or later restoration job can undo the reveal. Stale generation/unmounted/hidden requests do nothing. Ordinary Tab/native focus reveal is not a reset transition and must not snap back to top.

A-owned R2 cases in `ui-foundations.spec.js`: deeply scroll Look (all refinements open), Motion (pose/light open) and Export to their last controls, switch each via pointer and native Enter/Space, assert 0 and heading/first control visibility plus task-button focus and ordinary Tab order. Assert reset on close/reopen, collapse/expand and both breakpoint directions; selected task/disclosures/draft survive. For explicit source and global Export, assert final focused control/heading is visible after commit and two frames/microtask drain, no late reset, including rapid replacement requests. Same-breakpoint keyboard-size change preserves input focus/reach. Assert no project/history entry from any scroll/navigation. In normal and pathological whole-interior fallback, the last control remains reachable.

## 4. Event-order and focus transition matrix

**Parent-hiding invariant:** before task hide, Look/palette collapse, desktop collapse, mobile close, breakpoint remount, Help opening or source navigation: (1) invalidate pending reveal/focus generation; (2) invoke palette cancel with restoreFocus false; (3) change visibility/task/open state; (4) after commit, focus only the valid destination for this transition. Where pointerdown could blur hex before onClick (task buttons, collapse, Close, Help), A must invoke the cancellation barrier on pointerdown capture or equivalent synchronous pre-blur path **as well as** keyboard/programmatic close. This is an audited behavioral requirement, not “cleanup on unmount.” Do not blanket preventDefault on pointerdown, which breaks native focus/activation.

Focus callbacks must check connected/hidden/inert/disabled and generation; no timer-based unconditional `.focus()`. No arbitrary newly generated focus manager; extend existing refs/generation logic. Do not restore focus into a hidden task panel or desktop default portal after resizing.

### Escape ownership, precise layers

1. Hex picker Escape cancels draft and returns swatch; Settings remains open.
2. Active keyboard drag: Dialog's capture handler prevents only dialog dismissal when `isKeyboardDragging()` synchronously true. Let event reach dnd-kit. First Escape cancels reorder/restores handle, does not commit order; subsequent Escape closes Settings after ownership retires. Drop, external mutation, task hide, close and resize release ownership. No global stopPropagation.
3. Palette **name input** Escape is explicit Cancel palette: preventDefault/stopPropagation locally, clear name/close save form and focus Save palette trigger if still visible; second Escape may close Settings. It is not the same as a parent hide.
4. Sibling Help is topmost: Escape closes Help, not inspector. Help-open guard prevents background dismissal.
5. Otherwise Settings Escape closes and restores opener. Desktop task navigation has no Escape-to-reset/task/back feature.

## 5. Compact preset transaction policy

Palette editor strip is always visible in Look. Browse palettes is independent from name-save form. The form remains outside collapsed browse content. Collapsing browsing does not clear name draft or its open flag. Because its toggle is outside color popup, it cancels uncommitted hex through C's existing outside-click policy before any blur can write. Applying a palette is an existing structural operation: cancel transaction/drag, apply only colors and keep initiating preset focus if connected. It must invalidate revisions exactly like current implementation; do not replace own-write/revision machinery.

C adds synchronous cancel capture to its own Browse/Save/structural actions where blur order requires it. The shell's barrier handles parent actions. Internal color-picker blur to another non-cancel control may commit a valid hex exactly as baseline. Outside pointer/focus, Close, Escape, Tab departure, another swatch, undo/redo, external mutation, preset apply and owner hiding cancel uncommitted hex. Native picker updates remain immediate commits and synchronize text draft. Duplicate colors remain independently addressable; do not key only by hex.

Name draft/open survives task switching, close/reopen, desktop collapse and both breakpoint transitions. **Remove unconditional `autoFocus` on remount.** Focus name only when a user explicitly invokes Save palette, never when controlled open state remounts. Existing explicit Save/Cancel clears and returns trigger focus only if still connected, visible and current generation; parent hide must invalidate pending restoration, so the old form cannot steal focus from a new dialog. A/C must exercise this race, not assume a disconnected-node check covers a newly connected replacement. Revision counter for hex need not persist across remount because no active transaction survives; palette data and name/disclosure state must.

## 6. Status and operational state

Use exactly one existing StatusNotice portal, stable noticeNode appended to Preview slot when closed/desktop, active dialog slot when open. Task navigation does not move/remount notice. Help uses existing `suspended={helpOpen}`; retained text and zero mutation while frozen, latest coalesced text once after resume. No cloned screen-reader status, extra toast, producer-schema change or “loaded” message suppression for screenshots.

## 7. Audit-ready decisions versus gates

Design decisions are pinned here; no unresolved aesthetic user choice is required. **Independent audit is still mandatory**, especially the pre-blur barriers, finite QualitySettings split, controlled disclosure/name remount focus and visualViewport fallback. If source evidence contradicts these APIs, revise the documents with an explicit disposition before parallel coding. Do not treat these proposals or a resolution matrix as independent reapproval.
