## 1. Bounded phases and audit gates

### P0 — independent plan audit, before app/config/test edits

Reviewer reads the baseline files, not just these docs. Required review outputs: capability-inventory omissions, IA feasibility, native task semantics, one-preview/controller identity, input/file/project bridges, retained UI state through remount, palette pointerdown-before-blur and revision/focus races, responsive short-height/focus order, one notice/help suspension, ownership completeness, test adaptations and performance/format truthfulness. Check proposed split props against current code/lint; do not approve by screenshot taste alone.

Resolve each material objection in these documents with a numbered disposition and obtain independent reapproval. No application/config/test edits or installs before this gate. Parent's authorization covers later implementation after audited plans, not bypassing audit. No additional user aesthetic decision is presently required.

### P1 — A freezes shared foundation and contracts

A records baseline toolchain/status and runs baseline checks or consumes exact same-tree parent logs with revision/command evidence. Then implements shared token/classes/BTN aliases and shell-side contracts in one bounded slice: active tasks/controlled disclosure state, header project/Help props, source navigation handle integration, output-only ExportPanel caller contract, current palette API props and notice placement. Widget APIs in state-contracts are frozen **before** B/C/D start. A publishes an interface ledger (names/props/class names/validator additions), not a new library. The independent reviewer checks this shared slice before workers consume it. If APIs need stub-compatible landing, existing widgets may temporarily ignore new optional props; no shipped stub accepted as completed integration.

Only A owns shared files. Do not ask another worker to “fix a small shared CSS/validator/helper issue”; A applies it serially. No hook/controller/engine/export behavior rewrites. Main PreviewCanvas changes limited to JSX display and optional source-navigation callback; lifecycle/source effects untouched.

### P2 — B/C/D disjoint widget slices in parallel

Each worker reads approved docs and frozen foundation source. Each supplies changed files, capability mapping, actual focused tests/lint output, known gaps and screenshots where practical. Each slice gets independent read-only source/test review immediately when ready; do not wait for all workers. Resolve its findings before declaring accepted. Parent coordinates only the explicit cross-owner props; no simultaneous edits to shared tests/browser harnesses.

### P3 — A integration and actual browser review

A wires all final widgets, adapts the existing 30 behavior tests below plus export/generated-runtime navigation, adds new acceptance without dropping budgets/assertions, runs real source and built app flows, captures state-complete desktop/narrow screenshots and verifies focus/lifetimes on combined tree. Reviewer examines actual app, not paper diagrams, against redline findings. Fixes in worker files require explicit serial ownership transfer after that worker's slice is accepted; no stealth overlapping edits.

### P4 — final combined-tree verification, then parent delivery

Run all required gates after fixes. Passing individual slices or finishing phases is not product acceptance. Preserve any intermittent failure and classify, do not erase with a retry. Parent alone performs authorized final commit/push to the new redesign branch after reviews/checks pass, verifies exact remote ref SHA and delivers actual screenshots. No PR/merge/deploy; inspect workflow triggers before push so a branch push cannot inadvertently deploy. This author does not commit/push.
