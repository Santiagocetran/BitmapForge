## Mandatory findings — independent dispositions

### R1 — RESOLVED: visible rectangle, empty invitation and sibling Help

State contracts §3 now makes the geometry executable rather than relying on `100dvh`: finite positive `visualViewport.height` H and `offsetTop` T, fallback innerHeight/zero, visible interval `[T,T+H]`, synchronous initialization, resize and viewport-scroll listeners, changed-value publication and cleanup. Root variables reach sibling portals. Fixed narrow shell and modal use explicit top/height and `bottom:auto`; old inset/vertical-centering constraints must be removed.

The portrait sheet and short/landscape full-height formulas are explicit. Safe padding is inside border-box height; header/toolbar consume real layout space. Same-breakpoint keyboard changes preserve focus and lifetime. Under 240px the whole dialog interior may scroll rather than producing a negative task body.

The larger invitation is explicitly a separate inset, min-size-zero vertical scroller, naturally sized and only safely centered when it fits. All four source alternatives and demo remain, with wrapping and ≥44px targets. It neither dictates canvas dimensions to fit copy nor changes the preview manager/source effects. The baseline absolute centered invitation is not adequate without this change.

Help geometry is now mandatory A work, not optional styling: bounded visible rectangle, pinned title/Close, scrolling shortcut body, whole-content fallback below 240px. This directly covers the unbounded centered baseline sibling dialog; inspector fallback alone would not.

Required evidence now includes empty model and image, all routes/demo, Help by button and `?`, Close/last shortcut, actual visible-intersection bounds, overflow, stable main preview/manager and short captures. The 667×320 and 320×568 cases, emulated H320/T0, H280/T40 and H220/T40, same-breakpoint viewport scroll/resize and cleanup are finite assignments. They are future execution gates, not demonstrated keyboard support.

### R2 — RESOLVED: reset-to-start with postcommit reveal precedence

State contracts §3 R2 chooses one UI-only task-body scroller and explicitly rejects an offset registry. Every explicit task activation, including the current task, resets to zero after visibility commits; mobile reopen, desktop expand and both breakpoint crossings also start at zero. Active task, controlled disclosures and palette-name draft survive. Help and same-breakpoint height/offset changes do not reset.

Ordering is pinned: retire generation/cancel before hiding, commit visibility, apply reset, then consume the current one-shot explicit source/Export or required resize-owner focus/reveal. No timer, smooth scroll or later restoration may undo that reveal. Hidden/disconnected/stale requests do nothing. This is compatible with extending the actual Layout generation refs and layout-effect publication rather than introducing a focus framework.

Ordinary task activation keeps focus on the native task button; ordinary Tab visits remaining navigation buttons before active panel controls. It does not jump directly into the panel or use partial tabs semantics. Explicit global Export/source invocation intentionally has a different focus policy.

The additions require deep Look/Motion/Export scrolling, pointer and Enter/Space activation, start/heading/first-control assertions, ordinary Tab order, last-control reach, close/reopen/collapse/both boundaries, retained durable state, same-breakpoint input reach and no history writes. Reveal stability after commit and two frames, including replacement requests, prevents an incidental hidden-panel clamp from masquerading as the selected policy.

Implementation plan §6.1 assigns A sole evidence ownership for exactly `apng`, `gif`, `webm`, `spritesheet`, `css`, `react`, `webcomponent`, `embed`, `zip`. No test-side `setSize`, patched runtime or injected model can pass acceptance.

The new spec is bounded to the four named GIF/React/Web Component/Embed cases. No engine/builder rewrite, new dependency or nine duplicated heavyweight suites is implied. Existing source/generated comparisons and unit/decode/workspace checks supplement, not replace, actual downloads.

The proposed external source/built configs and CLI entrypoints are sufficiently pinned for implementation: exact match lists, absolute repo/test/evidence paths, isolated strict ports/cache/output, no reuse, served build hashes and discovery via `--list`. These configs are explicitly not claimed to exist yet and require parent authorization before creation. A must record their concrete contents and every command's exit/evidence path.

The full 181-stop/full-loop CSS assertions, 384×320 observed-preview fixture and all original quality thresholds are retained.

## Binding implementation clarifications

1. **Measured geometry wins over shorthand.** Specification §1's earlier `100dvh` shell sentence is the CSS fallback, not a competing height constraint. State contracts §3 R1 is the normative keyboard/offset rule. Assert physical target bounds in the visible intersection, not merely `toBeVisible` or layout-viewport intersection. Emulated getters/events verify the adapter, not real browser keyboard behavior; report unavailable physical keyboard/Safari/AT/touch evidence honestly.
2. **Reset must not move navigation focus or overwrite reveals.** Execute the reset before that generation's explicit reveal, including reselecting the current task and rapid replacement requests. Same-breakpoint clipping correction is only an instant nearest reveal of the existing active input, not autofocus, navigation reset or transaction cancellation. Whole-interior pathological fallback must still make Close and the last control reachable; pinned-row assertions apply to the normal-height regime.
3. **Budgets and evidence targets are hard gates.** The final 90,000ms test deadline must not be overridden by per-case/suite timeout changes, retries or the old source-dev export runner. A retained 120,000ms event wait does not extend that deadline. Built tests cannot use source-store imports or builder substitution; source comparisons cannot count as built UI downloads. Preserve original assertion strength even where a ledger description is shorthand. A newly discovered baseline runtime defect or budget failure is a reported blocker requiring separate diagnosis/scope review, not implicit permission to patch builders/engine or weaken acceptance.
