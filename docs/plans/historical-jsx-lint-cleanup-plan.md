### Consumed shared helper interface (read-only)

The observed helper exports callable validators with signature `(props, propName, componentName = 'Component') => Error | null`:

- `optionalBoolean`: accepts undefined/null/true/false; rejects other supplied values.
- `requiredBoolean`: accepts true/false; rejects null/undefined and non-booleans.
- `optionalFunction`: accepts undefined/null/functions; rejects other supplied values.
- `requiredFunction`: accepts functions; rejects missing/null/non-functions.
- `renderableChildren`: accepts undefined/null, strings, numbers, bigint, booleans, React-valid elements/fragments, and recursively nested arrays of those; rejects plain objects/functions/symbols and invalid nested entries.

These are the exact exports this cleanup consumes; no new shared exports are assumed. This is the helper's documented supported child set, **not a claim to recognize every possible ReactNode** (e.g. portals, iterable objects and promises are not accepted by this observed implementation). Actual ErrorBoundary, provider and tooltip callers need the supported set. Preserve elements/fragments as opaque valid elements rather than executing children/components; a throwing descendant must still reach ErrorBoundary normally. If independent audit finds a real omitted caller path, settle the helper contract with its owner before implementation, not with an always-null fallback or a second interpreter.

### Local SchemaControls contract

`schema` is already the **properties map**, not a JSON Schema root containing a `properties` member. `builtinPlugins.js` and PluginRegistry use that map; current production QualitySettings still hand-crafts its built-in controls (no actual SchemaControls invocation found outside its existing tests). Do not add integration or invent plugin loading in this cleanup.

- Allow omitted/null schema because the component returns null. Otherwise require a non-null non-array record; each field must be a non-null non-array record. Empty maps/descriptors are valid and render nothing. Optional `type` must be a string; do not restrict it to the four implemented types: unsupported types are intentionally skipped. Optional `title` must be a string, including empty string. Preserve unknown schema keywords without asserting full JSON Schema validation.
- For implemented types, validate supplied non-null numeric bounds as finite numbers. Boolean defaults, numeric defaults (finite; integer defaults integral for integer fields), and string defaults must match their field type when non-nullish. String enum, when supplied, must be a string array (empty is accepted). Nullish defaults/bounds/enum retain the current fallback/no-control paths. Unknown field types are accepted and ignored, including their unconsumed extra data. Do not enforce minimum/maximum order, membership, required keys, IDs or normalization unrelated to lint.
- Allow omitted/null `values` because `values?.[key]` falls back to `field.default`. Otherwise require a non-array record. For keys associated with implemented fields, non-nullish overrides must match boolean/string/finite number, with integral values for integer fields. Missing/nullish entries use defaults. Unknown keys and values for skipped types are not consumed and must remain unrestricted; this is a concrete record plus consumed-key contract, not an `any` validator. If schema is nullish, still enforce values' record shape but do not invent field semantics.
- `onChange` is optional/nullish callable metadata because the existing guard deliberately returns null without it; do not make it required to quiet lint. Its existing callback payloads remain `(key, boolean|string|number)` from native events. No validator executes or coerces the callback.
- Validators return meaningful component/prop-specific Error objects, never throw on malformed data. Validate schema shape before looking up field members in the values validator so a malformed sibling cannot make direct validation throw. Do not mutate schema, defaults or values.

The metadata documents expected typed inputs; it does not add runtime schema enforcement under React 19 or change existing coercions. Retain all 13 original tests, including null cases. Do not narrow the nullish contract just because production generally provides objects.

Accept empty arrays, more than five colors, and CSS color strings rather than imposing a hex-only regex or palette-size limit. This tiny local extraction is for test access, not a validation framework, component export, or React-internals dependency.

## 6. Gizmo publication and cleanup design

Import `useLayoutEffect` alongside existing hooks. Retain `handlersRef` with its initial object. Remove both render-time assignments. In a **layout effect with no dependency array**, construct and assign one `{ onMove, onUp }` object using the just-committed `setBaseRotation` closure and the unchanged drag math. Define those closures inside the effect; this avoids dependency ambiguity and publishes latest handlers on every committed render. No callback publication or `handlersRef.current` read/write during render.

Retain the existing separate passive `[]` effect that installs one mousemove/mouseup delegate pair and removes those exact functions on cleanup. Layout publication occurs before that listener setup on mount; ordinary rerenders refresh callbacks without listener rebinding. Do not clear the publication during ordinary layout-effect cleanup (it is private, not an externally owned bridge). Final passive cleanup removes listeners; avoid inventing timers, changing event types, resetting in-progress drag on rerender or adding extra drag cancellation behavior.

Preserve: sensitivity `0.009`, X/Y signs, original startRot and Z, 15-degree Shift snap, event coordinates, mouseup stopping updates, mousedown restarting from then-current rotation, canvas sizing/drawing effects and styles. The handlers must see the latest committed setter, not values from speculative renders or the initial mount.

Required tests use a **test-local** complete 2D context spy implementing save/restore/scale/path/arc/stroke/fill/text calls (the shared setup lacks these). Restore canvas mocks, listeners/spies and Zustand state/actions after each test; retain real global event dispatch.

1. Down/move computes expected X/Y/Z, direction and sensitivity; Shift snaps both axes; no down means no update; mouseup then move means no update; a subsequent drag starts from updated committed rotation.
2. Start a drag, replace the store's setBaseRotation action and commit a rerender through act; dispatch a window move immediately after that commit. Only the new setter runs and the original drag origin is preserved. Assert no mousemove/mouseup add/remove during that ordinary rerender. Do not wait for an arbitrary timer to mask stale publication.
3. When feasible, suspend an attempted rerender with a new setter and prove the existing committed delegate does not switch to the uncommitted callback; use a deterministic Suspense/transition harness, not a flaky timing test. If the harness cannot model this reliably, report that limitation rather than claiming speculative-render coverage.
4. StrictMode setup/cleanup/setup leaves one live listener pair and working drag. Final unmount removes the exact installed functions; window move/up after unmount cannot call a setter. Remount does not inherit an old active drag. Account for StrictMode replay rather than asserting total add count equals one.
5. Browser smoke after implementation: actual rendered rotation gizmo drag updates existing rotation controls; Shift snapping and mouseup termination persist. This is mouse coverage, not new pointer/touch support. Parent may exercise it in the existing UI browser session without editing concurrently owned browser specs.
