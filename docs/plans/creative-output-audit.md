# Independent audit: creative output plan

## Decision and evidence boundary

**Revise before implementation.** The workstreams are well separated and correctly reject speculative performance claims, but the shippable label is not approval: CO-1 needs an explicit source transaction/history design; CO-2 understates current live-export differences; CO-3 needs engine-level load ownership and capture-state restoration; CO-4 needs a bounded typography delivery contract and an existing inversion defect addressed. CO-5 and CO-6 remain measurement/experimental work only.

Audited `docs/plans/creative-output.md` independently against source at `298bdec17dcd1603add549118a743e5cd494ba08`, branch `gloin/ui-output-improvements`. Read `AGENTS.md`; `CODEX.md` and the four specified `COLLAB` bootstrap files are absent. No private memory or other-agent configuration inspected. This is a source audit, not a report of browser reproduction or passing implementation tests. No implementation, issue writes, push, deployment, or workflow edits are authorized by this audit.

## CO-1 — Starters

**Verdict: revise; viable product scope, blocking transaction ambiguity.** Palette-only compatibility, attribution, static thumbnails, and separate look-only actions are appropriate.

### Mandatory revisions

- **CO1-A — Define prepare/commit ownership before coding.** `PreviewCanvas.jsx:145–217` cancellation flags guard status updates, not scene mutations. `SceneManager.js:114–148` drops a second async load while `_loading` is true; a first load can subsequently replace a newer synchronous shape, and can attach after disposal. Fetching a file successfully is not equivalent to preparing a renderable model. Specify whether an unattached prepared group or a temporary manager is used, who disposes failed/stale resources, and how the preview subscription avoids a second destructive load. Coordinate this engine change with CO-3 rather than implementing competing loaders.
- **CO1-B — Make history behavior explicit.** `useProjectStore.js:49–55` excludes `model`, `imageSource`, and `pluginParams`. A scalar undo after replacing a model can restore the old input type but retain the new binary source. Choose bounded reference-based source history, or a clearly disclosed nonundoable replacement/history boundary approved before implementation. Do not describe partial source restoration as one undoable starter action. Test replacement starting from a user image even if no starter itself contains an image.
- **CO1-C — Publish an exact reset/preserve table.** Include seed, post-effects, renderer-specific parameters, lighting, animation phase/options, text spacing, and transforms. “Declared look” alone can conceal contamination from an old project's undeclared effects. `setRenderMode` upgrades ASCII cells below 8 to 10; later direct `setPixelSize` can still choose smaller values. Specify action ordering and whether the invariant applies only when entering ASCII. Source-plus-look and look-only need different transform rules.

### Required tests and limits

Add old model→new model→undo/redo, image→starter→undo, failed parse after successful HTTP fetch, model A→shape B, model A→model B, and edit-during-preparation tests. Assert active scene content and resource disposal, not only store/status values. Keep preset persistence separate and leave marketplace/project binary serialization redesign out of scope. If safe binary history cannot fit this issue, explicitly narrow launch behavior rather than quietly dropping the criterion.

## CO-2 — Export guidance and capability gates

**Verdict: revise; metadata direction approved, advertised matrix not yet complete.** The nine-format distinction and video fallback caveat match source. Correctness must mean settings are applied, not merely present in JSON.

### Mandatory revisions

- **CO2-A — Expand parity inventory beyond ASCII.** `exportConfig.js:12–35` also omits seed, model scale, post-effect configuration, and renderer-specific controls. React/Web Component templates call `updateAnimationOptions` with `config.animationDuration`, but the builder stores duration under `effectOptions.animationDuration` (`reactComponentExport.js:47–55`, `webComponentExport.js:50–58`). Record each format's source, serialization, application, dimensions/DPR, and deterministic timing support separately. Either repair a narrowly approved omission or block/warn precisely; never infer parity from a complete project payload.
- **CO2-B — Treat SDK and CLI application differences as actual limitations.** `BitmapForgeElement.js:83–111` and `packages/cli/src/harness.js:113–139` do not call `setBaseRotation`, `setLightDirection`, or `setModelScale`, and text load omits `letterSpacing`. Those values are not applied by `SceneManager.updateEffectOptions` or `updateAnimationOptions`. The full settings payload therefore does not establish preview parity. Existing image rejection is only one limitation.
- **CO2-C — Resolve Code ZIP classification now.** `codeExport.js:25–38` unconditionally fetches a model and only constructs the manager: no explicit render-mode selection, resize, animation setup, lighting, or pose setup. SceneManager's constructor is not a universal state applicator. Label this as an engine starter requiring integration, not a faithful live output, or create a separately audited repair. It must not become a recommended live-site choice under the proposed goal matrix while these remain unresolved.
- **CO2-D — Gate at exported builder boundaries as well as UI handlers.** `buildReactComponent`, `buildWebComponent`, `buildCodeZip`, and `buildEmbedZip` can be called independently. Check active source and actual asset availability; a retained `state.model` must not substitute for current text/shape/image input. Distinguish unsupported capability from a runtime environment that cannot encode any recommended raster alternative; allow “no compatible format” with an actionable explanation rather than force a false recommendation.
- **CO2-E — Add generated-source safety tests.** React/Web Component and Code ZIP interpolate model filenames into JavaScript string literals (`reactComponentExport.js:11`, `webComponentExport.js:10`, `codeExport.js:34–36`). Quotes, backslashes, URL delimiters, and path-like names can break artifacts or alter generated code. Use safe archive asset names and properly serialized literals; validate public component/tag/name parameters. This is bounded export correctness, not a general security rewrite.

### Required tests and limits

Use asymmetric model fixtures with nondefault pose, light, scale, duration, seed, post-effects, and ASCII settings so missing application is visible. Execute freshly generated React, Web Component, SDK Embed, and Code ZIP under their documented installation/HTTP procedures; a nonblank scene alone is insufficient. Cover all source types with a stale model retained. Test malicious/unusual filenames, missing SDK responses returning HTML with HTTP 200, and generated README/metadata consistency. Keep codec redesign and universal parity repair separate; unsupported settings must stay visible to users until repaired.

## CO-3 — Live lifecycle policy

**Verdict: revise; highest-priority correctness work, wider than an observer helper.** The identified autoplay, reduced-motion, reconnect, and context-restore defects are supported by `BitmapForgeElement.js:11–115` and `SceneManager.js:75–98`.

### Mandatory revisions

- **CO3-A — Define engine load generation and disposal contracts.** Guard `_setObject` after every async boundary, including model/text/image preparation; stale groups and object URLs must be disposed even after the original manager is destroyed. An SDK-level generation check after `await manager.loadModel()` is too late because the manager has already mutated. A shared boolean `_loading` is not last-request-wins. Ensure a stale request's `finally` cannot clear a newer request's loading state.
- **CO3-B — Preserve requested playback state across capture.** `framesProvider.js:34–52` always resumes in `finally`; CLI capture has the same pattern, and CLI video has its own pause/resume pair. `renderAtTime` itself does not resume. Introduce a scoped capture suspension/state token or equivalent explicit contract, including nested/concurrent policy changes. Completing/cancelling/throwing during capture must not resume a hidden, explicitly paused, context-lost, or disposed manager. Preserve existing editor behavior without coupling deterministic export to document visibility.
- **CO3-C — Specify first-frame and observer fallbacks.** State how playback waits for the first genuine intersection result, how zero-sized elements resize into visibility, what happens if IntersectionObserver is unavailable, and how context restoration redraws a paused still. Define eager loading under reduced motion: current autoplay is disabled for loading when reduced motion is set, so the proposed unconditional eager-autoplay rule is a deliberate API change, not pure preservation. `src` changes currently bypass lazy eligibility; route them through the same policy.
- **CO3-D — Close generated lifecycle gaps completely.** React callbacks test a shared ref for truthiness but capture the old manager; StrictMode's replacement can make that check pass for a disposed manager. Web Component fetch continuations can load into the replacement manager. Use generation-specific identity, aborts where possible, and cancel queued rAFs; reuse shadow roots and dispose local managers on error. Give all generated live examples, including Code ZIP if classified as live, either the policy or an explicit unsupported-policy disclaimer.
- **CO3-E — Define still selection from animation semantics.** CSS frame zero can be blank during fade-in. Choose and store a representative sampled show-frame index, set explicit reduced-motion background-position, and verify it remains visible with the current sprite dimensions. Do not claim pure CSS provides JS visibility suspension. Keep manual play/loop API expansion excluded; explain which existing pause method/state the controller owns.

### Required tests and limits

Add engine-level deferred load races, disposal during decode, interleaved source generations, failed retry, initial-hidden loading, offscreen prefetch versus actual visibility, DPR/resize while paused, capture cancellation/error with every pause reason, and context restore while reduced/offscreen. Browser tests must count recurring callbacks over a bounded interval and check a visible still; absence of CSS animation is not proof that WebGL work stopped. Run fresh generated React under StrictMode and remove/reinsert both custom elements. No new editor playback UI or general scheduler rewrite is authorized.

## CO-4 — Custom ramps and typography

**Verdict: revise; validation scope sound, existing fade semantics and distribution gates unresolved.** Preserve named ramps and draft/committed state separation.

### Mandatory revisions

- **CO4-A — Fix or explicitly gate existing inverted fade mismatch before parity claims.** `BaseEffect.js:203–239` stores already-inverted particle brightness; `AsciiRenderer.drawPixel` passes that to `_glyphFor`, which inverts again (`AsciiRenderer.js:134–159`). Static rendering inverts once (`:210–218`). Also test threshold equality: `shouldDraw` uses `>` while static skipping uses `<`. Define one brightness/threshold contract for particles and static rendering, with regressions for every affected renderer if shared particle semantics change.
- **CO4-B — Separate ASCII font identity from 3D text font fields.** Existing `fontFamily`/`fontSize` describe generated text geometry. Choose distinct ASCII fields or a fixed bundled typography version. Specify exact permitted code points (not merely “supported blocks”), validator behavior for nonstrings and unknown IDs, warning ownership, and safe fallback. Apply validation to both parsers and `loadProjectFile`, not just `parseProjectData`: editor/SDK migration paths already differ (`projectFile.js:10–20,82–116` versus SDK parser).
- **CO4-C — Make font readiness a resource contract.** Define shared promise/cache, font load timeout and failure, invalidation of measured glyph metrics after readiness, and disposal/generation behavior while a font is pending. Await the actual face/repertoire, not only an unrelated `document.fonts.ready`. A fallback warning must prevent a false deterministic-export claim; decide whether failed-font capture is blocked or explicitly marked nonreproducible.
- **CO4-D — Audit every distribution output.** Root `build:embed` copies only one JS file; Embed ZIP fetches/packages only that JS plus project/HTML; `ENGINE_SOURCES` contains JS sources, not arbitrary font assets. A new external font will not automatically reach app public output, npm dist, downloaded archives, or the CLI HTTP server. Specify self-relative font URLs, copied manifests, licensing notices, and an explicit JS-plus-font transfer budget. Do not move bytes outside the existing 51,200-byte JS gzip check and imply the total is unchanged.
- **CO4-E — Bound delivery.** If font selection/licensing/packaging cannot be resolved before coding, split custom-ramp validation from deterministic typography with explicit limited claims and a separate audit. Do not silently replace the named-ramp font appearance globally without approved references. Coordinate shared validation/raw imports and export-config ownership with CO-2/CO-3.

### Required tests and limits

Add inverted static/fade endpoint and threshold equality tests, nondivisible canvas/grid sizes, alpha and post-effect interactions, late font load after an initial fallback draw, disconnect while font pending, CLI font HTTP resolution, malformed direct renderer options, and old project migration fixtures. Browser references need two real engines and DPR coverage; current Playwright config specifies no cross-engine projects and uses software-GL launch flags. Cross-platform byte identity and arbitrary Unicode remain excluded.

## CO-5 — Glyph benchmark

**Verdict: approve measurement direction after protocol clarification; no production renderer authorization.** Existing caches are correctly acknowledged. Atlas speed cannot be inferred from fewer text calls, particularly when fades, colors, readback, and GPU/software paths differ.

### Mandatory revisions, tests, and limits

- **CO5-A:** Freeze target scenario IDs, hardware classes, memory cap, warmup/sample counts, and pass aggregation before results; “dense target scenarios” and “fits target device” are presently underdefined. Report every scenario, not an aggregate hiding a slow common case. Retain per-run raw data and separate paired A/B order to reduce warmup/thermal bias.
- **CO5-B:** Distinguish renderer CPU submission timing from completed frame time and export wall time. rAF cadence alone cannot establish a 20% renderer improvement; Canvas/GPU operations may defer work. Document synchronization/readback measurement overhead and compare equivalent paths. Treat unavailable mobile hardware as a documented incomplete device gate, not a mobile performance claim.
- **CO5-C:** Include actual cell dimensions for nondivisible sizes, DPR, font-ready state, color cardinality, atlas construction/eviction, and allocations through fade/static transitions. Cell size 4 is a useful stress case but not the normal entry-to-ASCII default; label it accordingly. Benchmark the shipped CO-4 baseline and record pre-font-change results separately if taken.
- **CO5-D:** Verify excluded prototype modules/assets are absent from production build output, not merely hidden behind an unchecked UI flag. Add harness smoke/correctness checks to CI, not timing thresholds. Keep noisy/impossible memory observations explicitly unavailable rather than inventing precision. No promotion without a new audited plan.

## CO-6 — Source-color and edge experiments

**Verdict: approve research scope only after contract decisions; not a launch dependency.** Independent modes and explicit export gating are appropriate.

### Mandatory revisions, tests, and limits

- **CO6-A:** Record the sampled-scene contract through `BitmapEffect` and `BaseEffect.initializeParticles`; particles currently retain adjusted brightness and palette color, not original RGB/neighborhood information. Define source alpha, compositing, inverted density, and whether a fading glyph retains its sampled orientation or recomputes from the moving scene. Resolve CO4-A before using fade parity as a reference.
- **CO6-B:** State luminance/color space and orientation quantization, validate directional glyphs against CO-4's repertoire, define transparent-neighbor exclusion and hysteresis/temporal stability, and measure gradient preprocessing separately from glyph drawing. Include gradients on borders and near thresholds, animated light/pose changes, and fixed seeds/timestamps.
- **CO6-C:** Freeze target scenarios/devices and the overhead aggregation rule before measurements; require reviewers to record independent judgments before discussion. Keep source-color and edge-mode pass/fail independent. Missing device/reviewer evidence prevents graduation, not completion of an honestly inconclusive experiment.
- **CO6-D:** Gate programmatic exporters and project imports, not only controls. Unknown experimental fields must not silently enable production behavior. Keep fixtures/prototypes out of default bundles and public archives unless the archive explicitly includes a tested experimental runtime. No default renderer/format/schema migration is authorized here.

## CI and deployment safety — mandatory prerequisite for release

**CI-A — Material shipping risk confirmed.** `.github/workflows/ci.yml:47–65` deploys production from the `check` job on main pushes while `cli` runs independently. Root tests exclude SDK and dedicated export decode suites; Playwright is not invoked. The plan identifies this correctly but defers remediation to an unspecified approved change. For shared engine/lifecycle/font changes, a manual checklist alone is not an adequate release dependency.

Proposed separately approved CI safety issue (no workflow change in this audit):

1. **Separate validation from deployment.** Move production deployment into its own protected-environment job requiring successful root checks, embed tests/build, CLI build/tests, export decode tests, and generated-artifact browser tests. Explicitly restrict deployment to authorized main pushes or an approved release action. Require these check names through branch protection; read back settings during an authorized release check. PR/fork jobs get no production credentials.
2. **Use one reproducible install/build chain.** Use Node 20 and root `npm ci` with the committed workspace lockfile, rather than subsequent unconstrained `npm install` calls. Build SDK once, package that SDK into the app/archives, and compare the packaged bytes to the size-tested SDK. Include font and helper manifests and alias checks. Record revision and artifact hashes.
3. **Make missing suites real prerequisites.** Existing commands: `npm run lint`, `npm run format:check`, `npm test -- --max-workers=50%`, `npm run build`, `npm test --workspace @bitmapforge/embed`, `npm run test:export`, `npm run test:e2e`, and the CLI workspace build/test commands from its package scripts. Install the required Playwright browser/system dependencies in CI. Add generated React/SDK/Web Component lifecycle/font fixtures; the current e2e suite covers app/APNG/sprites/Code ZIP/CSS/video, not those integrations. Add a second browser engine for typography with engine-appropriate launch options. Never mark skipped browser installation/tests as success.
4. **Validate production artifacts, not only dev-server modules.** Existing Playwright starts Vite dev and may reuse an existing server. Add isolated built-app serving with explicit readiness and revision checks; test non-root hosting, archive extraction, missing asset failures, and direct SDK/font/model MIME/content checks. Store logs, screenshots, decode results, and failure traces as artifacts. Timing benchmarks remain informational.
5. **Deploy the verified artifact deliberately.** Current `npx vercel --prod` rebuilds rather than consuming uploaded `dist`. Prefer a reviewed Vercel build/output workflow followed by `deploy --prebuilt` of that validated output; raw `dist` alone is not automatically a valid Vercel prebuilt artifact. If rebuilding is retained, pin toolchain and verify deployed build provenance plus all shipped asset hashes before claiming identity. Check external Vercel Git integration so a second automatic deployment cannot bypass these gates.
6. **Prevent unintended and out-of-order releases.** Define a docs-only release policy explicitly: either skip only the deploy job using an audited deploy-relevant change calculation, or require environment approval for every production deploy. Keep required validation jobs runnable so branch protection does not deadlock on skipped workflow checks. Serialize production releases or otherwise ensure an older run cannot overwrite a newer deployment. Record rollback target and owner before release.
7. **Post-release verification is separate authorization.** On an authorized deployment, verify served revision, SDK/font/model bytes, a fresh Embed ZIP, and a reduced-motion/visibility smoke case; rollback on failed smoke checks. This audit and the current local task authorize none of these external state changes.
