## H1 — exact ownership, uncertainty and bounded repair

### Current event/focus/controller chain

- `src/app/components/Layout/Layout.jsx:124–128`: `barrier()` retires reveal/focus requests and calls the palette interaction handle with `{ restoreFocus: false }`. Rail pointer capture **and** click call it before `setCollapsed` (`:424–443`); keyboard activation gets the click path. Desktop collapse only sets `hidden` on `#desktop-settings`; it does not intentionally remount the palette.
- Task buttons also use capture/click barriers (`:304–323`); resize calls cancel before changing presentation (`:168–199`); Help bridge captures invoker and cancels before opening (`:206–226`), with a committed Help fallback (`:265–267`). Thus “collapse forgot to call cancel” is not supported by source.
- `src/app/components/ColorPalette/ColorPalette.jsx:272–320`: cancel clears transaction, increments focus generation, closes editing/errors, and increments `epoch` **only when** `dragRef.current !== null`. The interaction handle delegates through `cancelRef`; it is published in a passive effect and cleanup clears the supplied ref. It reports keyboard ownership from `dragRef` plus `keyboardDrag`.
- `:393–417`: epoch keys only `DndContext`. Start assigns keyboard flag/index after non-reset cancellation; cancel clears index and schedules handle restoration; end ignores a null index, otherwise moves/drops. `:260–270` queues generation/visibility-checked focus. `:294–312` cancels on external palette mutation, with controlled own-write handling. A local ref being idle does not itself establish the internal sensor/context is idle.
- Locked dependency `node_modules/@dnd-kit/core/dist/core.esm.js:1133–1198,1319–1339` shows KeyboardSensor owns delayed document keydown and window resize/visibility listeners, detaching on sensor end/cancel. Context start/end callbacks live at `:3077–3173`. React hidden alone is not a sensor cancellation API. This is a plausible lifetime seam, **not proof of a leaked sensor in this run**.
- Narrow Dialog `Layout.jsx:522–530` must prevent only parent dismissal when child keyboard drag/name input owns Escape. It must not stop the sensor's event propagation. Picker Escape and transaction/blur cancellation remain palette-owned (`ColorPalette.jsx:321–331,442–468,497–508`).

**Cause confidence:** high that the retained integrated path violates cancellation; low-to-medium for a specific mechanism. Candidate: local ref/epoch lifetime and sensor callback ordering diverge after prior hide/remount, so a later parent barrier does not retire the actually active context. Neither a missing barrier nor stale callback publication is proven. Do not implement either as fact.
