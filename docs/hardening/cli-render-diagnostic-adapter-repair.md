## Corrections

- **R1 — parent-pinned current ownership:** `executionGate` and `run` require a separately supplied `parentLaneOwner` argument. It must be nonempty and equal both `approval.currentLaneOwner` and `approval.laneTransfer.from`. Destination remains `cli-diagnostic`; explicit=true and nonempty transfer evidence remain mandatory. No worker identity is hardcoded in executable authority checks. The template leaves both owner fields null and transfer false. Parent must discover/pin the actual current owner at handoff time; worker completion does not transfer authority or authorize lock stealing.
- **R2 — child finalization:** new shared `persistence.mjs` is used by the actual render and decoder paths. Cleanup/monitor-stop attempts precede independent ordinary log writes. Returned frozen-helper results (without stdout/stderr bodies), cleanup, exit/signal/close/containment and decoder records are retained in memory before persistence and attempted in reserved `process.json`, `cleanup.json` and `terminal.json` independently. A stdout, stderr, ordinary decoder process, or first reserved write failure cannot skip the remaining attempts. Application/helper failures remain primary; persistence/cleanup errors are separate bounded lists. Decoder records survive a thrown decode and the outer cell terminal retains them. Compact bounded cell persistence summaries also reach the session terminal/console when a cell directory itself cannot be written.
- **R2 — session finalization:** `Store` now withholds the same 64KiB/four-file allowance from ordinary session writes within—not in addition to—the unchanged 256-file/128MiB total. Session terminal/ledger targets are explicitly allowlisted. `reserveSession` runs before checkpoint copying. The actual orchestration uses `sessionScope`; failures stop the work and finalization blocks unstarted cells, independently attempts the reserved ledger and terminal, attempts the ordinary manifest separately, and releases only the inode/device-matching owned lock in finally. Failed filesystem persistence is reported as failure, never durable success. A successful evidence manifest is not invalidated by a later terminal rewrite.
- **Runtime prerequisite:** preflight is regenerated by executing the actual approved cached Node and npm CLI paths, not by changing evidence fields. Approval checks exact Node `v24.22.3`, npm `11.21.2`, executable paths and SHA-256 pins, plus the exact whole-preflight hash/current readback. Existing Puppeteer/Chrome and all CI/sandbox/environment checks remain. No install was needed.

Numeric/render/decoder/sampling/raw/queue/file budgets, six mandatory cells/one conditional cell, observer attachment, capture scheduling, fixtures, retained bundle, and protected subprocess helper are unchanged.
