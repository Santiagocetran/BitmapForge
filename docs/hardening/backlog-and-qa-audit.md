## Bounded cross-browser and accessibility QA plan

### Available tools and honest constraints

This audit did not launch browsers to avoid contention with parent QA. Repository uses installed Playwright; cache discovery found Chromium/headless-shell revisions `1217` and `1234`, but **no cached Firefox or WebKit**. Neither repository `node_modules/axe-core` nor `@axe-core/playwright` exists at audit time. Cache presence alone does not prove a browser executable or its shared libraries launch. Parent may discover an already provisioned external tool, but must record its path/version and smoke it; do not install dependencies under this assignment.

Proposed matrix is **Chromium, Firefox and Playwright WebKit**, with a per-engine launch preflight. Run Chromium if available; mark Firefox/WebKit **blocked/not run** unless already provisioned. Playwright WebKit on Linux is not real Safari on macOS/iOS. Chromium device emulation is not a physical phone. Existing touch spec uses CDP: do not pretend it is portable to Firefox/WebKit unchanged.

### Scope and execution ledger

Use one identified built revision/asset manifest and parent-owned strict-port preview server; disable server reuse and isolate evidence/cache/output paths. Do not rebuild or overwrite another worker's evidence. Run browsers serially, with no retries for acceptance; retain failures and prerequisites. Use installed CLI through the supported Node 24 runtime, not default shell Node (this audit observed `v22.23.4`). Do not assume existing CLI `--browser` flags apply to tests that manually call `browser.newContext` with Chromium-specific options: inspect and choose compatible focused routes.

Record for every case: revision/build hash, target URL, engine/version/OS, viewport/DPR/motion state, case ID, outcome (`pass`/`fail`/`blocked`/`not run`), artifact path and exact reason. A successful launch is not UI acceptance, and unavailable WebGL is a prerequisite failure rather than a UI pass.
