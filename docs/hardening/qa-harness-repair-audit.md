## 1. Required correction — R6 mixed scanner failure / outer DOM cancellation

**Evidence:** `specs/accessibility-smoke.spec.mjs:55–71` catches a scanner failure, appends `qa-blocked`, and durably sets `activeStage = "dom"` before supplemental assertions. Ordinary caught DOM exceptions and soft failures correctly add `qa-dom-failed` and remove the block (`:74–91`). However, that cleanup cannot be relied upon for the very outer-cancellation-before-catch scenario R6 explicitly addresses.

`run.mjs:239–259` reads the durable stage. `scannerBlocked("dom", false, "timedOut")` correctly returns false, but `:256–257` then unconditionally reinstates `blocked` from the earlier scanner annotation. Only a delivered `qa-dom-failed` annotation reverses it. There is no durable DOM completion/failure record to distinguish scanner-only failure with successful supplemental completion from cancellation during supplemental evaluation. Runtime's local ledger also prioritizes the scanner annotation (`lib/runtime.mjs:233–239`).

I exercised the **actual classification block extracted from `run.mjs`**, with read-only in-memory filesystem/writer substitutes (no runner/browser invocation):

| Fixture: scanner injection failed, `activeStage:"dom"`, no scanner result, runner `timedOut` | Actual classification |
| -------------------------------------------------------------------------------------------- | --------------------- |
| No annotation                                                                                | `fail`                |
| Earlier `qa-blocked` only; outer DOM cancellation before its catch                           | **`blocked`**         |
| Earlier `qa-blocked` plus delivered `qa-dom-failed`                                          | `fail`                |

This proves an offline classification branch defect, **not an observed live browser timeout**. The existing 13 tests exercise `scannerBlocked("dom", …)` in isolation, not its subsequent annotation override, so their pass does not cover this path.

**Bounded repair:** persist supplemental entry/completion/exception independently of scanner completion. In the external runner's fallback, give a demonstrated supplemental failure or terminal timeout/cancellation while supplemental work is unfinished failure precedence over an earlier scanner annotation. Preserve scanner-only blocked classification when supplemental checks demonstrably completed successfully; preserve valid axe violations and DOM soft failures as failures. Apply compatible precedence to the local ledger, without erasing either underlying scanner or supplemental evidence. Add an offline regression through the actual integrated classification path for scanner failure → DOM entry → cancellation without catch, plus scanner failure → successful DOM completion and unresolved scanner evaluation controls. Do not increase any deadline, retry, disable tracing, change Q7 policy, or edit the app. Re-freeze the changed executable map and review the new bytes.
