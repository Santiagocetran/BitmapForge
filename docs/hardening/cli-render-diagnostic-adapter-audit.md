### R2 — reserved terminal persistence is skipped after ordinary write failure

In `adapter.mjs:158–188`, stdout/stderr writes precede `process.json` and `cleanup.json` inside one `try`. A cap, I/O or reservation error writing either log jumps directly to the catch; the reserved process/cleanup writes are never attempted. The later `terminal.json` includes a cleanup object but not the full frozen-helper result, exit/signal/byte/containment record. Thus precreated terminal files can remain empty on precisely the overflow path they were reserved to preserve.

This is independently reproduced **without a browser**: ran a real benign Node child through frozen `runChild` (exit 0, `closeObserved=true`, `groupAlive=false`, actual stdout `audit failure-persistence probe\n`), then executed the actual render-finalizer fragment extracted from `adapter.mjs` against an explicitly fault-injected store rejecting its first ordinary write. The only attempted write was `stdout.log`; neither `process.json` nor `cleanup.json` was attempted. The injected error was retained in memory, but that does not satisfy durable returned-result persistence. This is a finalizer fault-injection test, not a simulated rendering result.

`decode.mjs:26–43` has the analogous ordering: ordinary stdout/stderr persistence can throw before the decoder record is added to `commands` or persisted. Its process record is not charged to a reserved terminal target. Decoder cleanup is attempted first, which is good, but its returned result/cleanup can still be lost to the evidence-write exception. Session-level finalization also has no dedicated reserve: `checkpoint()` or ordinary session evidence can exhaust the session allowance before the blocked ledger/terminal reason can be written.

**Correction:** isolate best-effort ordinary log/body writes from unconditional bounded result/cleanup/terminal write attempts. Preserve the original application/helper error and separately record persistence errors. Retain decoder result/cleanup in the reserved cell terminal accounting even if ordinary decoder process/log files cannot be written. Ensure a bounded session terminal/blocked-ledger reserve exists before checkpoint/ordinary session writes, within the unchanged 256-file/128MiB allowance. Keep all existing per-cell caps and the 64KiB/four-file terminal reserve; do not add an uncapped emergency output path. If the filesystem itself is unwritable, report that inability explicitly rather than claiming durable persistence.

Add nonbrowser fault-injection regressions at render stdout/stderr, decoder log/process persistence and session checkpoint-cap failure: verify the real returned subprocess/cleanup data remains available in bounded terminal evidence, primary error remains visible, the ledger blocks later cells, and owned cleanup/lock-finally still runs. Do not change the protected `runChild` or render budgets. Existing 18 green tests test constituent pieces, not these integrated failure orderings.
